## Implementation

### Routes, navigation and screens

`resources/spa/src/router/routes/frontOffice.ts` now owns the canonical host-relative tree. The
live contract is Dashboard, Get Started, Operational Search, Clients/Create/Detail, Appointments,
Walk-Ins, Queue/Transfer, Service Sessions, Invoices/Create, invoice-scoped Record Payment, Payment
and Receipt Status, Daily Activity and Account. Appointment create/detail, queue-entry detail,
invoice detail and receipt detail remain supporting workflow routes. Narrow legacy redirects retain
bookmarks; no gated alias exists. Search is a shared cross-account utility nested in `RoleShell`, not
a standalone page.

The exact group order is Home, Quick Access, Clients, Appointments & Walk-Ins, Queue & Service,
Billing Client, Billing Banner, Utility. Subscription Payment/Recovery and Notifications are visible
and `aria-disabled`, with their distinct owner/gate statements. Direct URLs return the ordinary
not-found boundary and make no gated API request.

New role compositions are `FrontOfficeDashboard.vue`, `DailyActivity.vue`,
`PaymentReceiptStatus.vue`, `QueueTransfer.vue` and `FrontOfficeAccount.vue`. Existing client,
appointment, walk-in, queue, session, invoice, payment, Get Started, Search and own-security pages
were refined with `SvOperationalHero`, task panels, workflow strips and semantic statuses. Shared
changes are route/role-aware and regression-tested.

### Server read seams and API contract

`FrontOfficeWorkspaceReadModel` projects three read-only views from already shipped facts:

1. `GET /api/v1/front-office/workspace` — assigned branch, Nairobi business-day operational counts,
   work requiring attention, invoice/receipt handoffs and server-owned Get Started milestones;
2. `GET /api/v1/front-office/activity` — paginated current-day same-branch safe action labels, never
   raw Audit-account payloads;
3. `GET /api/v1/front-office/payment-status` — paginated maker-safe recorded evidence, Finance
   decision state and automatic original-receipt readiness, never a checker mutation or raw provider
   reference.

OpenAPI is deterministically regenerated at **299 paths / 350 operations**, with generated
TypeScript current. There is no migration, write endpoint, financial calculation, state-machine or
permission-matrix change.

### Security and authority proof

- Every read is authenticated, tenant-scoped and constrained to the assigned Front Office branch.
  Foreign tenant/branch ULIDs fail closed; masked contact remains masked.
- Same-branch normalized-phone duplicates return deterministic 409; another branch remains isolated.
- Queue and appointment transfer continue through their Phase 16 policies, Form Requests,
  eligibility services and state machines. The new Queue Transfer page grants no new mutation.
- Payment recording remains idempotent maker evidence. Front Office cannot validate/reject, perform
  duplicate override, bypass a locked period, mark paid or issue/reissue an original receipt.
  Finance validates; the original receipt is generated automatically after validation.
- Account exposes only the signed-in user's Magic Link identity, own MFA/sessions, theme and assigned
  branch. Business, staff-access and notification settings are absent.
- Personnel contact export does not exist. No Branch/HR/Audit/Finance administrative control appears.
