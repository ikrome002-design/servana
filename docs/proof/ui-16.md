**Observed problem:** `/login` has no fixed footer in both themes. **Evidence:** the new form
case failed `getByTestId('sv-fixed-footer').toBeVisible()`; `AuthLayout.vue` had only header/main.

reserved its block size. **Why this is the root cause:** it is absent from source and DOM, rather
than hidden by a token or selector. **Correct fix / files changed:** use the existing footer,
the server-resolved account's legal-content key, existing FAQ route helper, and `sv-footer-reserve`.
**Tests added:** all eight account contexts, both themes, seven widths and 640×400 reflow, action
non-obstruction, legal destinations and axe. **Test command:** the added archetype spec above.
**Test result / proof:** the first post-fix 24/24 compare passed all seven-width footer cases;
final enhanced checks are recorded separately. **Remaining risk:** hosted full authentication
suite and production-image gate must pass on the final head. No auth API/permission changed.
