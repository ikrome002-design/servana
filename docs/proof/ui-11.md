## Objective and authority

Implement the exact nineteen-page Human Resource account at `hr.servana.ke`: branch-scoped staff,
invitation, lifecycle, eligibility, availability, compensation-plan setup, payout preparation,
HR-event visibility and own-account security. HR never crosses branches, self-escalates, activates
a Merchant Administrator, exports client/payment data, computes earnings, or performs Finance
payout verification/approval/mark-paid transitions.

Authority: UI/UX plan §§2, 6–7, 9–13, 15–21, Phase UI-11, §28 and Appendix A §8; Development Plan
§§3.1, 9, 10.2–10.3, 15A–15B, 20F, 20H, 21N and 80.2; canonical navigation map and permission matrix.

## Proven problem

The canonical contract contains 19 pages, while the predecessor router exposes ten legacy `/hr/*`
children and no HR dashboard, lifecycle deep link, compensation detail/setup/history, HR audit or
own-account destination. The current Access page is only a generic permission preview but is marked
as though it assigns roles, and the current Staff Profile loads a whole first page before searching
for one record. Reports/notifications depend on unimplemented Phase 21N; staff profile and access
mutations have no active canonical server contract. Treating those surfaces as live would fabricate
authority.
