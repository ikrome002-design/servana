## Root-cause records

Full records with before/after evidence: [`defect-closure.json`](../frontend/audits/ui-05/defect-closure.json).

### `UI01-ASSET-002` — unapproved brand files publicly served

**Observed** Eleven unapproved brand working files (`PNG.png` + ten `v1/ChatGPT Image …png`) shipped
inside the public web root of the production image and were served.
**Evidence** UI-01 register row; UI-00 brand inventory (`present_unreferenced` × 11); live
re-verification of all eleven paths and SHA-256 values before any move.
**Affected files** `public/assets/brand/**`, `docker/nginx.Dockerfile`.
**Root cause** Working files were committed under `public/`, and no build stage filters unapproved
assets out. The edge image copies the whole `public` tree, so anything under it ships by
construction.
**Why this is the root cause** The defect is *location*, not content. Adding an edge deny rule would
leave the bytes in the image and depend on a config nobody re-reads; moving them out of `public/`
removes the exposure at its source.
**Correct fix** Non-destructive quarantine: `git mv` all eleven into
`docs/brand/quarantine/ui01-asset-002/`, preserving the `v1/` subdirectory. `docs/` is never copied
into the nginx image. **Nothing was deleted** — deleting product-owner artwork is not UI-05's call
(CLAUDE.md §9), and a quarantine leaves the decision reversible.
**Files changed** 11 moved; `config/brand-asset-quarantine.json` (new reviewed decision record);
`docs/frontend/source-inventory/brand-assets.json` regenerated through its own generator; the empty
`public/assets/brand/v1/` directory removed.
**Tests** `Ui05AssetQuarantineTest` (7) · `Ui05BrokenAssetContractTest` · two negative controls ·
`scripts/ui05-production-smoke.mjs` · the UI-05 Playwright spec.
**Result** `public/assets/brand` now contains exactly the 8 approved assets; all 11 archived files
hash identically to their pre-move values.
**Remaining risk** Enforced by contract test + production smoke; the negative controls exist so a
guard that stops firing is itself caught.

### `UI05-FAQ-001` — sixty FAQ questions silently dropped

**Observed** 60 of Merchant Administrator's 196 FAQ questions never reached any surface.
**Evidence** `merchant_administrator_faq.md` carries 136 questions at `##` and 60 at `###`; the
runtime parser required `h[1].length === 2`. All seven other accounts write every question at `##`,
so the defect was invisible in seven of eight cases.
**Affected files** `resources/spa/src/content/markdown.ts` (`parseFaq`),
`resources/spa/src/content/roleDocuments.ts`.
**Root cause** The parser encoded a *formatting* convention (heading level) as if it were the
*semantic* rule (dotted question numbering).
**Why this is the root cause** The source documents define a question by its dotted number.
`### 9.14 Does the preferred personnel fee…` is unambiguously a question and was dropped purely for
the number of hashes preceding it. 136 + 60 = 196, against 136 compiled before the fix.
**Correct fix** Heading level removed from the rule; compilation moved to generation time so the
parse is checked in CI rather than re-run per view.
**Tests** `FaqContentContractTest` counts questions in the **source** per account rather than
trusting the manifest; `generatedContent.spec.ts` asserts the 60 level-three items compile.
**Result** 196/196 compiled; **1,264** items across the eight accounts (was 1,204).

### `UI05-IMAGE-001` — every supplied image enumerated, hero assumed, alt text invented

**Observed** `landingImages()` enumerated all 61 images from a hard-coded count table;
`heroImage()` assumed `1.png`; `RoleLandingScaffold` rendered it with invented alt text and declared
`width=800 height=600` for files that are 1672 × 941 or 1448 × 1086.
**Root cause** Three assumptions stood in for measurements: that a directory's contents can be
derived from a constant, that file order encodes meaning, and that a generic sentence is adequate
alternative text.
**Why this is the root cause** Each fails independently, and the declared 800 × 600 against a
1672 × 941 file mis-reserves layout space — a CLS defect as well as a correctness one.
**Correct fix** Both helpers read the generated manifest; the scaffold renders a `<picture>` with
AVIF/WebP candidates, curated alt text, measured intrinsic dimensions, the recorded loading strategy
and fetch priority, and the focal point as `object-position`.
**Result** 32 curated images (4 per account) with measured dimensions and per-image alt text.

This is the **same value at a new commit**, not a new secret and not a regenerated digest. Squashing
PR #54 created a fresh commit introducing the identical line, and a gitleaks fingerprint is
`commit:path:rule:line` — so the same non-secret is reported under a second fingerprint. Rather than
assume it from the existing entry, the claim was re-verified from scratch:
`Get-FileHash resources/spa/src/design-system/tokens.json -Algorithm SHA256` returns exactly

the digest of a file committed in this repository, is printed in plaintext in the generated file's
own header, authenticates and authorises nothing, and was matched on entropy alone (3.897).

The correction is **one additional exact fingerprint**. No rule, path, glob, extension, regex,
entropy threshold, workflow step, job permission or exit code changed, and the design-token
generator was **not** modified to dodge the matcher — altering a UI-04 artefact to silence a scanner
would be worse than recording the finding truthfully. The residual UI-04 already recorded stands:
every squash merge mints another fingerprint for this same non-secret, and a durable treatment needs
its own authorization.
