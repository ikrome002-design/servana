## Welcome to Servana

Servana helps service businesses run daily branch operations with more clarity, structure, and confidence.

The Merchant Branch account is built for the person responsible for managing a specific business branch. It gives the branch team a practical dashboard for branch profile setup, operating hours, services, pricing, queues, appointments, service sessions, invoices, payment records, receipts, branch reports, daily opening, day closing, cash-up, reconciliation, and branch audit activity.

This FAQ explains how the Merchant Branch account works in clear, practical language. It is a Help document, not a legal document.

# 1. About Servana

## 1.1 What is Servana?

Servana is a service-operations SaaS platform for African service-based SMEs.

It helps businesses manage clients, staff, services, branches, queues, appointments, invoices, offline payment records, receipts, commissions, platform fees, reports, and audit-ready operational records from one secure web dashboard.

Servana is not only a booking app, POS system, or invoicing tool. It is a daily operating system for service businesses.

---

## 1.2 Who is Servana built for?

Servana is built for service-based SMEs such as:

* Barbershops
* Salons
* Spas
* Massage parlours
* Grooming studios
* Beauty parlours
* Similar walk-in or appointment-based service businesses

It is especially useful for businesses where branch teams need to coordinate staff availability, client queues, appointments, services, invoices, offline payments, and daily accountability.

---

## 1.3 What does Servana help a branch manage?

A branch can use Servana to manage:

* Branch profile details
* Operating hours
* Calendar exceptions
* Services and pricing
* Service availability
* Staff visibility
* Personnel availability visibility
* Queues
* Appointments
* Service sessions
* Client flow
* Invoices
* Payment records
* Receipts
* Branch reports
* Branch revenue
* Day opening
* Day closing
* Cash-up and reconciliation records
* Branch audit logs

The branch account helps the team see what is happening now and what needs attention next.

---

## 1.4 Does Servana process client payments?

No. Servana records offline or off-platform payments.

Payments may happen through cash, M-Pesa, bank transfer, card terminal, voucher, split payment, or another merchant-defined offline method.

Servana records the payment details so the business can track, validate, reconcile, and review the payment properly.

---

## 1.5 What is a merchant branch?

A merchant branch is a physical or operational business location under a merchant account.

Examples include:

* Westlands Branch
* Kilimani Salon Branch
* CBD Barbershop Branch
* Hotel Spa Branch
* Mobile Service Branch

Each branch has its own profile, operating hours, service setup, queues, appointments, invoices, receipts, payment records, reports, and branch-level audit logs.

---

## 1.6 Is a branch the same as a user account?

No. A branch is a business location or operating unit.

A Merchant Branch account user is the person assigned to manage that branch in Servana.

This distinction matters because one is the business location, and the other is the person with access to manage that location.

# 2. Merchant Branch Account Basics

## 2.1 What is the Merchant Branch account?

The Merchant Branch account is the role used to manage one specific branch inside Servana.

It helps the branch user manage daily branch setup and operations, including services, pricing, operating hours, queues, appointments, invoices, receipts, payment records, reports, day opening, day closing, and branch audit logs.

---

## 2.2 Who should use the Merchant Branch account?

The Merchant Branch account should be used by a trusted branch-level operator.

Typical users may include:

* Branch manager
* Branch supervisor
* Operations lead
* Senior front desk operator
* Location manager
* Branch administrator

This user should understand the branch’s daily activity and should be trusted to manage branch-level settings and operational workflows.

---

## 2.3 Who creates a Merchant Branch account?

The Merchant Administrator creates branches.

The Merchant Administrator also adds the initial Merchant Branch account user email during merchant setup or branch setup.

The Merchant Branch account user does not create branches.

---

## 2.4 Can a Merchant Branch user manage multiple branches?

The Merchant Branch account user manages only the branch they are assigned to.

A user should not automatically access other branches. Access to another branch must be intentionally assigned through the correct merchant-side workflow.

---

## 2.5 Can a Merchant Branch user manage another merchant’s branch?

No. Each merchant operates in a separate tenant.

A branch user should only access the branch records for the merchant and branch they are assigned to.

---

## 2.6 What is the main purpose of this account?

The main purpose is to keep the branch running smoothly.

The Merchant Branch account helps the branch team answer practical questions such as:

* Is the branch open today?
* Which services are available?
* Which personnel are available?
* How many clients are waiting?
* Which appointments are coming up?
* Which clients are in service?
* Which invoices are unpaid?
* Which payments are pending validation?
* Which receipts have been issued?
* What happened during the branch day?
* Are there unresolved cash-up issues?
* What activity was logged?

# 3. Access and Login

## 3.1 How does a Merchant Branch user log in?

Merchant Branch users log in through a Magic Link sent to their email address.

The user requests access, receives a login link, and clicks the link to enter Servana.

---

## 3.2 Can a user log in just because their email exists?

No. Servana checks more than the email address.

Before access is allowed, the platform checks that:

* The user email exists.
* The user belongs to the correct merchant tenant.
* The user account is active.
* The user role is active.
* The user has not been suspended.
* The user is assigned to the correct branch.
* The Magic Link is valid, unused, and not expired.

This protects branch records from accidental or unauthorized access.

---

## 3.3 What should I do if my Magic Link does not work?

Request a new Magic Link first.

A Magic Link may fail because:

* It expired.
* It was already used.
* It was opened from the wrong browser or device.
* You are checking the wrong email inbox.
* Your account is inactive.
* Your role is inactive.
* Your access was suspended.
* Your branch assignment is missing or inactive.
* Your browser or email client blocked the login flow.

If the issue continues, contact support through the approved Help & Support workflow.

---

## 3.4 Can I share my Magic Link with another staff member?

No. Magic Links should not be shared.

Each user should access Servana through their own assigned account. Sharing access makes activity records unclear and weakens branch accountability.

---

## 3.5 What should happen if I leave the branch or business?

Your access should be suspended, deactivated, or removed by the appropriate administrator.

Historical records connected to your activity should remain visible so the business can still understand past branch operations.

# 6. Branch Status

## 6.1 What branch statuses can exist?

Common branch statuses include:

* Active
* Suspended
* Archived or Closed

The exact labels may depend on platform configuration.

---

## 6.2 What does Active mean?

Active means the branch can operate normally.

An active branch may accept walk-ins, appointments, queues, invoices, payment records, receipts, and service sessions.

---

## 6.3 What does Suspended mean?

Suspended means the branch is restricted from normal live operations.

A suspended branch may be blocked from accepting new walk-ins or appointments. Historical records should remain visible for review.

---

## 6.4 What does Archived or Closed mean?

Archived or Closed means the branch is no longer operational in Servana.

A branch should not be closed or archived while live operational records still exist.

---

## 6.5 What should be resolved before closing or archiving a branch?

Before a branch is closed or archived, the team should resolve items such as:

* Active queue entries
* In-progress service sessions
* Unpaid invoices
* Pending payment validations
* Validated payments with unissued receipts
* Pending appointment check-ins
* Unclosed branch day
* Unresolved cash-up discrepancies

This prevents unfinished work from being lost or forgotten.

---

## 6.6 Why does Servana protect branch closure?

Branch closure affects client records, staff activity, payments, invoices, receipts, reports, commissions, and audit history.

Servana should protect closure workflows so that important operational records remain clear.

---

# 7. Operating Hours and Branch Calendar

## 7.1 What are branch operating hours?

Branch operating hours define when the branch is normally open and closed.

They help control appointment availability, queue expectations, staff planning, and branch reporting.

---

## 7.2 Can the Merchant Branch user manage operating hours?

Yes. The Merchant Branch account user can manage operating hours for the assigned branch where enabled.

---

## 7.3 What should operating hours include?

Operating hours should include:

* Opening time
* Closing time
* Operating days
* Break periods, where used
* Special closure days
* Public holiday exceptions
* Emergency closures
* Notes or closure reasons, where needed

---

## 7.4 What are calendar exceptions?

Calendar exceptions are changes to normal operating hours.

Examples include:

* Public holiday closure
* Extended weekend hours
* Shortened hours for a staff meeting
* Temporary closure for maintenance
* Event-day schedule changes
* Special seasonal hours

---

## 7.5 What is a same-day emergency closure?

A same-day emergency closure blocks new branch activity for that day because of an unexpected issue.

Examples may include:

* Power outage
* Staff shortage
* Flooding
* Security concern
* Emergency maintenance
* Sudden branch closure decision

When a same-day emergency closure is set, new queues and appointments should be blocked according to the branch rules.

---

## 7.6 Why should closure reasons be recorded?

Closure reasons help managers, staff, and audit users understand why the branch was unavailable.

They also help explain cancelled appointments, blocked queues, reduced revenue, and unusual daily activity.

---

## 7.7 Are operating hour changes recorded?

Yes. Operating hour changes should be recorded in branch activity logs.

This helps the merchant understand who changed the schedule and when.

The Merchant Branch account user configures services and pricing for the assigned branch.

The Merchant Administrator can view services and pricing but does not configure services at merchant level.

## 8.2 Why are services configured at branch level?

Different branches may offer different services, prices, hours, personnel, durations, and service categories.

Branch-level service setup makes Servana practical for real business operations.

---

## 8.3 What information should a service include?

A service record should include:

* Service name
* Service category
* Price
* Estimated duration
* Branch availability
* Active or inactive status
* Discount support, where available
* Preferred personnel fee eligibility, where available
* Eligible personnel visibility from HR setup

## 8.4 Can a branch user create services?

Yes. The Merchant Branch account user can create services for the assigned branch where the feature is enabled.

---

## 8.5 Can a branch user edit service prices?

Yes. The Merchant Branch account user can edit service prices for the assigned branch where the feature is enabled.

Service price changes should be handled carefully because they affect invoices, customer expectations, revenue reports, and audit records.

## 8.6 Can a branch user archive a service?

Yes, where the feature is enabled.

## 8.8 Why does HR control service eligibility?

HR manages staff identity, skills, roles, branch assignment, availability, and service eligibility.

This prevents Front Office or Branch users from assigning a client to someone who is not approved to perform the selected service.

# 9. Personnel Visibility

## 9.1 Can the Merchant Branch user see staff activity?

Yes. The branch user can view staff activity for the assigned branch.

This helps the branch understand who is available, busy, unavailable, assigned, or affecting branch operations.

---

## 9.2 Can the Merchant Branch user assign staff to branches?

No. Branch assignment is handled by the Merchant Human Resource workflow.

The Merchant Branch user manages the branch, not staff assignment.

---

## 9.3 Can the Merchant Branch user manage HR records?

No. HR records are managed by the Merchant Human Resource account user.

The branch user may see operational staff information needed for branch coordination, but does not manage employment records or staff profiles.

---

## 9.4 What HR-controlled personnel information can the branch user view?

The branch user may have read-only visibility into:

* Personnel assigned to the branch
* Personnel availability schedules
* Working days
* Working hours
* Breaks
* Temporary unavailability
* Active or inactive status for queue
* Service eligibility
* Reassignment needs when personnel becomes unavailable

---

## 9.5 Can personnel be available for appointments but unavailable for walk-ins?

Yes. Personnel availability can be more specific than simply available or unavailable.

A staff member may be available for appointments but not walk-ins, or available for walk-ins but not appointments, depending on branch and HR configuration.

---

## 9.6 What happens when personnel becomes unavailable?

When a Merchant Personnel user becomes unavailable, the branch may need to reassign affected queue entries or appointments to another eligible personnel member.

The reassignment should be handled clearly and recorded in the activity logs.

---

## 9.7 Can the branch user reassign clients when personnel becomes unavailable?

Yes. The Merchant Branch user may transfer affected queue entries or appointments to another eligible Merchant Personnel user.

This is an operational continuity action. It does not give the branch user HR authority to change staff assignment or service eligibility.

---

# 10. Queue Management

## 10.1 What is the branch queue?

The branch queue is the list of clients waiting for service.

It helps the branch team see who is waiting, who has been assigned, who is in service, who has completed service, and who was cancelled or marked no-show.

---

## 10.2 Who manages the queue?

The Merchant Branch account user can handle branch queue configuration and may manage branch queue activity where enabled.

Front Office users may also handle day-to-day client queue activity depending on the workflow.

---

## 10.3 What queue statuses should exist?

Useful queue statuses include:

* Waiting
* Assigned
* In service
* Completed
* Cancelled
* No-show

These statuses keep the branch’s client flow clear.

---

## 10.4 Can the branch user open or close the queue?

Yes. The Merchant Branch user can open or close the branch queue where enabled.

Closing the queue prevents new walk-in queue entries while preserving existing records.

---

## 10.5 What is queue capacity?

Queue capacity is the maximum number of waiting clients allowed in the queue.

Capacity may apply to:

* The whole branch
* A specific personnel member
* A service category
* A time period

Queue capacity helps prevent overcrowding and unrealistic waiting times.

---

## 10.6 What is assignment mode?

Assignment mode controls how clients are assigned to personnel.

Common assignment modes include:

* Next available personnel
* Manual assignment
* Preferred personnel

Assignment mode should match how the branch operates.

---

## 10.7 What does next available personnel mean?

Next available personnel means the client is assigned to the next eligible staff member who can perform the selected service.

This is useful for fast-moving walk-in operations.

---

## 10.8 What does manual assignment mean?

Manual assignment means an authorized branch or Front Office user selects the personnel member manually.

This may be useful when the branch needs more control over workload, skills, or customer needs.

---

## 10.9 What does preferred personnel mean?

Preferred personnel means the client chooses a specific staff member.

This is common in salons, barbershops, spas, and grooming businesses where clients often prefer a specific barber, stylist, therapist, beautician, or specialist.

---

## 10.10 Should queue changes be recorded?

Yes. Important queue changes should be recorded.

Examples include:

* Queue opened
* Queue closed
* Queue reordered
* Client assigned
* Client reassigned
* Preferred personnel selected
* Preferred personnel overridden
* Client cancelled
* Client marked no-show

Activity records help the branch explain what happened during the day.

---

## 10.11 Why are queue cancellation reasons important?

Cancellation reasons help the branch understand why clients left the queue or why service did not continue.

Common reasons may include:

* Client left
* Client rescheduled
* Staff unavailable
* Branch closed
* Service unavailable
* Duplicate entry
* Incorrect entry

Clear reasons make reports more useful.

---

* Appointment status
* Check-in status
* Notes

Yes. The Merchant Branch account user can handle branch appointment controls where enabled.

This may include viewing, managing, rescheduling, cancelling, or controlling appointment availability for the assigned branch.

---

## 11.3 What controls appointment availability?

Appointment availability may depend on:

* Branch operating hours
* Calendar exceptions
* Public holiday settings
* Special closures
* Service duration
* Personnel availability
* Personnel service eligibility

* Queue or workload rules

Check-in confirms that the client has arrived.

* Client cancelled
* Client rescheduled
* Staff unavailable
* Branch closed

No-show marking records that the client did not arrive for the appointment.

This helps the branch track missed appointments and understand schedule gaps.

Preferred personnel waiting allows a client to wait for a specific service provider instead of taking the next available personnel.

For example, a client may choose a specific barber, stylist, beautician, therapist, or grooming specialist.

---

## 13.2 Is preferred personnel selection optional?

Yes. The client can choose either:

* Next available personnel
* A specific preferred personnel

---

## 13.3 Can preferred personnel selection include an extra fee?

Yes. Where enabled, preferred personnel selection can include an extra fee.

The fee is configured at platform level by the Super Administrator.

* Eligible personnel
* Preferred personnel chosen
* Extra fee

* Final invoice impact

The preferred personnel fee should appear as a separate invoice line item.

The branch should handle the situation clearly.

* Client is reassigned to another eligible personnel
* Client cancels

## 13.7 Can the branch user override preferred personnel?

The branch user may override preferred personnel only where permission allows it.

An override should require a clear reason and should be recorded in the audit log.

# 15. Offline Payments

## 15.1 What does offline payment recording mean?

Offline payment recording means the branch records payment details for a payment that happened outside Servana.

For example, a client pays by cash or M-Pesa, and the branch records the amount, method, and reference in Servana.

---

## 15.2 What payment methods can be recorded?

Servana may support:

* Cash
* M-Pesa
* Bank transfer
* Card terminal
* Voucher
* Split payment
* Other merchant-defined offline payment methods

---

## 15.3 Can the branch user view payment records?

Yes. The Merchant Branch account user can view branch payment records for the assigned branch.

---

## 15.4 Can the branch user record payments?

The branch or Front Office workflow may allow payment recording depending on configuration.

Recording a payment is not the same as validating a payment.

---

## 15.5 Who validates payments?

Merchant Finance validates payments where Finance validation is enabled.

The branch user may see payment records and pending validation status, but Finance usually confirms whether the payment is valid.

---

## 15.6 What does pending validation mean?

Pending validation means the payment has been recorded but has not yet been approved by Finance.

The payment is visible, but it is not fully confirmed.

---

## 15.7 What does validated mean?

Validated means Finance has reviewed and accepted the payment record.

A validated payment can support receipt generation and confirmed financial reporting.

---

## 15.8 What does rejected mean?

Rejected means Finance reviewed the payment record and did not accept it.

A rejection may happen because of wrong amount, missing reference, duplicate reference, unclear evidence, incorrect method, or another issue.

---

## 15.9 What is split payment?

Split payment means one invoice is paid using more than one method.

Example:

* KES 500 cash
* KES 700 M-Pesa

Each payment part should have its own method, amount, reference where needed, and validation status.

---

## 15.10 What is partial payment?

Partial payment means only part of the invoice has been paid.

The remaining balance should remain visible until the full validated amount matches the invoice amount.

---

# 17. Branch Day Opening

## 17.1 What is branch day opening?

Branch day opening is the process of preparing the branch for operations inside Servana.

It confirms that the branch is ready to handle clients, queues, appointments, services, invoices, and payment records.

---

## 17.2 What should be checked during day opening?

A good day opening workflow should check:

* Active personnel
* Service availability
* Branch operating status
* Queue open or closed status
* Appointment schedule
* Branch closure exceptions
* Any urgent staffing issue
* Any service availability issue

---

## 17.3 Why is day opening important?

Day opening creates a clear start point for branch activity.

It helps managers understand when operations started and whether the branch was ready before clients were served.

---

## 17.4 What day statuses may exist?

Useful statuses include:

* Not opened
* Open
* Paused
* Closed
* Reopened with reason

These statuses help the branch track its operating day clearly.

---

## 17.5 Can a branch day be paused?

Yes, where enabled.

A branch day may be paused because of temporary interruption, staffing issue, maintenance, or another short-term operational issue.

---

# 18. Branch Day Closing

## 18.1 What is branch day closing?

Branch day closing is the process of reviewing and ending the branch’s operating day in Servana.

It helps the branch confirm that daily activity has been reviewed and submitted.

---

## 18.2 What should be reviewed before closing the branch day?

Before closing the branch day, review:

* Invoices created
* Payment records
* Pending validations
* Receipts issued
* Unpaid invoices
* Completed sessions
* Cancelled sessions
* No-shows
* Queue status
* Appointment status
* Offline payment totals
* Cash-up readiness

## 18.3 Why is day closing important?

Day closing creates accountability.

A clear reopening workflow protects branch accountability.

# 19. Cash-Up and Reconciliation

## 19.1 What is branch cash-up?

Branch cash-up is the process of reviewing the day’s recorded payments and comparing them with expected amounts.

It is especially important because Servana records offline payments.

---

## 19.2 What is reconciliation?

Reconciliation means checking whether invoices, payment records, receipts, and actual offline payment totals match.

It helps the branch find missing payments, wrong amounts, duplicate references, rejected payments, and cash differences.

---

## 19.3 What should a cash-up summary include?

A cash-up summary should include:

* Expected revenue
* Recorded payments
* Validated payments
* Pending validation
* Rejected payments
* Cash total
* M-Pesa total
* Bank transfer total
* Card terminal total
* Voucher total
* Split payment total
* Discrepancy amount
* Notes for any difference

---

## 19.4 Can the branch user submit cash-up records?

Yes. The Merchant Branch account user can submit branch cash-up and reconciliation records where enabled.

---

## 19.5 Who reviews cash-up records?

Merchant Finance may review, approve, reject, or flag cash-up records depending on the configured workflow.

---

## 19.6 What is a discrepancy?

A discrepancy is a difference between expected totals and recorded or counted totals.

Examples include:

* Cash count does not match recorded cash payments.
* M-Pesa total does not match payment references.
* An invoice is unpaid but marked complete.
* A receipt is missing.
* A payment is pending validation.
* A payment reference appears more than once.

---

## 19.7 What should I do when there is a discrepancy?

Record a clear note explaining what does not match.

Then follow the branch’s internal review process. Finance may need to review the issue before the day or period is finalized.

---

## 19.8 Does the Merchant Administrator receive the cash-up report?

Yes. The Merchant Administrator should receive the daily branch cash-up and reconciliation report by email in PDF format.

---

# 24. Security Basics

## 24.1 What should Branch account users do to keep access secure?

Branch users should:

* Use their own email account.
* Never share Magic Links.
* Log out on shared devices.
* Keep devices secure.
* Avoid using public or shared browsers.
* Report suspicious access quickly.
* Check that branch records belong to the correct branch.
* Avoid unnecessary downloads.
* Keep client and payment information confidential within the business.

---

## 24.2 Why is account sharing a problem?

Account sharing makes activity records unclear.

If several people use one account, the business cannot confidently tell who changed a service price, closed a queue, recorded a payment, or submitted a cash-up.

Every user should use their own account.

---

## 24.3 What should I do if I notice suspicious activity?

You should:

1. Review the affected record.
2. Check the branch, user, time, and module.
3. Notify the Merchant Administrator or assigned manager.
4. Preserve screenshots or references where appropriate.
5. Use the Help & Support workflow if platform support is needed.

---

## 24.4 What should happen after staff suspension?

When staff are suspended or deactivated, their login should be blocked and active sessions should end.

The branch should also check whether the staff member had active queues, appointments, or service sessions that need reassignment.

---

## 24.5 Why is branch scope important for security?

Branch scope keeps each user focused on the correct location.

It prevents users from accessing records that do not belong to their assigned branch.
