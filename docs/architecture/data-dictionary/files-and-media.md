# Files & Media — Data Dictionary

Domain owner: **Files** (Plan §65; Phase 10F / REM-FILE-001). Canonical DDL authority
for `uploaded_files` and `file_scan_events` (Plan §13.2). Authored **before** the
migrations (ADR-004 §6). Tests run on PostgreSQL only (§13.3).

These two tables are the single sanctioned home for private business files. No
feature phase may write, promote or sign private files outside the file-domain
service (enforced by `FileStorageBoundaryTest`).

---

## `uploaded_files`

- **Purpose/scope:** one row per uploaded or platform-generated business file
  (Plan §65). Tracks quarantine→scan→finalize lifecycle, scan verdict, retention
  and the (encrypted) original filename. Public references use the ULID only.
- **Tenant ownership:** **cross-cutting, nullable scope.** `merchant_id` /
  `branch_id` / `owner_user_id` are nullable because future platform-generated
  records may have no merchant (e.g. a platform export). It is **not** silently
  exempt from tenancy: it is classified in `TenantOwnership` as
  *cross-cutting nullable-scope infrastructure*, isolation is enforced by the
  file-access service (every read re-checks merchant/branch/owner against the
  authenticated principal) and by scoped route binding, and a uploadable-purpose
  row MUST satisfy its purpose's tenant/branch/owner requirements.
- **Soft delete:** none. Lifecycle is modelled by `lifecycle_status`
  (`deleted` is a terminal status, not a row removal); the object bytes are
  removed by the cleanup jobs.
- **Immutability:** `sha256`, `quarantine_path`, `purpose`, `storage_disk` are
  write-once at creation. Status columns change only through transition
  actions/services (no mass assignment, no controller writes).

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `bigint generated by default as identity` | no | — | internal PK, never exposed |
| `ulid` | `char(26)` | no | — | unique public identifier |
| `merchant_id` | `bigint` | yes | — | FK→`merchants.id` `ON DELETE RESTRICT`; nullable (platform files) |
| `branch_id` | `bigint` | yes | — | FK→`merchant_branches.id` `ON DELETE RESTRICT`; nullable |
| `owner_user_id` | `bigint` | yes | — | FK→`users.id` `ON DELETE SET NULL`; subject/owner (e.g. personnel statement) |
| `purpose` | `varchar(40)` | no | — | CHECK in the 11-value purpose set (below) |
| `storage_disk` | `varchar(40)` | no | — | disk name (e.g. `s3`); never exposed publicly |
| `quarantine_path` | `varchar(512)` | no | — | private quarantine object key; never exposed |
| `final_path` | `varchar(512)` | yes | — | private final object key after promotion; never exposed |
| `original_filename_encrypted` | `text` | no | — | Laravel `encrypted` cast; original name never stored/echoed in clear |
| `safe_download_filename` | `varchar(255)` | no | — | sanitised filename used in Content-Disposition |
| `declared_mime_type` | `varchar(191)` | yes | — | client-declared (untrusted) |
| `detected_mime_type` | `varchar(191)` | yes | — | server magic-byte detection (authoritative) |
| `extension` | `varchar(20)` | yes | — | sanitised extension matched to detected MIME |
| `size_bytes` | `bigint` | no | — | server-computed byte count |
| `sha256` | `char(64)` | no | — | streaming SHA-256; never exposed publicly |
| `scan_status` | `varchar(20)` | no | `'pending'` | CHECK `pending\|clean\|infected\|scan_failed\|rejected` |
| `lifecycle_status` | `varchar(20)` | no | `'quarantined'` | CHECK `quarantined\|available\|revoked\|expired\|deleted` |
| `retention_until` | `timestamptz` | yes | — | retention boundary for cleanup/expiry jobs |
| `uploaded_by` | `bigint` | yes | — | FK→`users.id` `ON DELETE SET NULL`; actor who uploaded |
| `available_at` | `timestamptz` | yes | — | set when promoted to `available` |
| `revoked_at` | `timestamptz` | yes | — | set when revoked |
| `created_at` / `updated_at` | `timestamptz` | yes | — | framework timestamps |

**Purpose set (CHECK):** `merchant_logo`, `profile_photo`, `dispute_evidence`,
`audit_evidence`, `finance_export`, `invoice_pdf`, `receipt_pdf`,
`billing_invoice_pdf`, `earnings_statement`, `day_close_report`, `cash_up_report`.

**Indexes:** `(merchant_id, purpose, lifecycle_status)`; `(branch_id, purpose)`;
`(sha256)`; `(scan_status, created_at)`. (No cross-tenant SHA-256 *uniqueness* —
global hash dedup would create an existence side channel; ADR/threat §73.)

**Status transitions (via transition actions only):**

```
upload accepted        → scan_status=pending,     lifecycle_status=quarantined
clean scan             → scan_status=clean,        lifecycle_status=quarantined
finalize (clean only)  → scan_status=clean,        lifecycle_status=available (+available_at, +final_path)
infected scan          → scan_status=infected,     lifecycle_status=quarantined→deleted (per policy); never downloadable
scan error             → scan_status=scan_failed,  lifecycle_status=quarantined; retry/operator; never downloadable
rejected (validation)  → scan_status=rejected,     lifecycle_status=quarantined→deleted; never downloadable
revoke / expire / delete → lifecycle_status=revoked|expired|deleted; never downloadable
```

**Application/DB consistency:** an `available` file must be `scan_status=clean`
AND have a non-null `final_path` (asserted in the model transition + a feature
test; a partial CHECK enforces "available ⇒ final_path present" where practical).

**Route exposure:** `POST /api/v1/files`, `GET /api/v1/files/{uploadedFile}`,
`POST /api/v1/files/{uploadedFile}/download-link`,
`GET /api/v1/files/{uploadedFile}/download`. Scoped ULID binding (foreign id 404).

**Authorization:** `FilePurposeRegistry` permission per purpose + `FileAccessService`
(merchant/branch/owner-own-scope) re-checked at link issuance AND download; download
additionally requires a valid short-lived signature (signature alone ≠ authorization).

**Job ownership:** `ScanUploadedFile`, `FinalizeCleanFile`, `ExpireSignedExport`,
`DeleteExpiredQuarantineFile`, `VerifyOrphanedFileRecords` (file-scanning queue;
tenant-aware or explicit platform context).

**Retention:** generated-purpose rows carry `retention_until`; `ExpireSignedExport`
expires elapsed generated files; `DeleteExpiredQuarantineFile` removes
quarantined-but-not-finalized objects past the quarantine window.

**Forward-repair:** forward-only (ADR-004). A correction ships as a new migration;
no shipped migration is edited; restoration via tested PITR.

## `file_scan_events`

- **Purpose/scope:** append-style log of every actual malware scan of an
  `uploaded_files` row. **Scope is inherited** through `uploaded_file_id`; this
  table is **never directly route-bound**.
- **Immutability:** one row per scan; not updated after insert.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `bigint identity` | no | — | internal PK |
| `uploaded_file_id` | `bigint` | no | — | FK→`uploaded_files.id` `ON DELETE RESTRICT` |
| `scanner` | `varchar(40)` | no | — | e.g. `clamav` |
| `engine_version` | `varchar(60)` | yes | — | scanner engine version |
| `signature_version` | `varchar(60)` | yes | — | virus signature DB version |
| `result` | `varchar(20)` | no | — | CHECK `clean\|infected\|error` |
| `malware_name` | `varchar(191)` | yes | — | signature name when infected |
| `error_code` | `varchar(60)` | yes | — | safe code on scan error (no raw payload) |
| `scanned_at` | `timestamptz` | no | — | when the scan ran |

**Index:** `(uploaded_file_id)`.

**Redaction:** scanner raw responses, malware payloads and file bytes are never
stored or logged; only the mapped `result` + safe metadata.

## Tenancy classification

`uploaded_files` → `TenantOwnership` group **cross-cutting nullable-scope
infrastructure** (alongside `idempotency_keys`): not a `BelongsToMerchant` model
with a non-null `merchant_id`, but isolation is enforced at the access-service
layer and by scoped binding. `file_scan_events` → exempt (inherits scope via
`uploaded_file_id`; never route-bound).
