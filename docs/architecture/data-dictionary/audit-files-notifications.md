# Audit, Files & Notifications — Data Dictionary

Domain owner: **Audit** (Plan §8, §13.2, §22.2, §70, §80 Phase 19; ADR-008). Canonical
DDL authority for `audit_logs` (existing R2 core) and **`audit_flagged_events`** (Phase
19). Files are documented in `files-and-media.md`; the notification/report catalogue is
Phase 21N and is intentionally not defined here yet. Authored **before** the migration
(ADR-004 §6). Tests run on PostgreSQL 16 only (§13.3).

Audit rows are append-only and hash-chained (ADR-008): a database trigger blocks
`UPDATE`/`DELETE` on `audit_logs`, and the per-merchant + platform chains are verified by
`audit:verify-chain`. Nothing in the flagged-event review workflow ever mutates a source
audit row.

---

## `audit_logs` (existing — R2 core, summarised)

- **Purpose/scope:** one immutable, hash-chained row per audited transition (Plan §70).
- **Ownership:** cross-cutting, **nullable** `merchant_id` (the platform chain uses
  `merchant_id IS NULL`) and nullable `branch_id`. Written only through
  `DatabaseAuditRecorder`, which computes the `hash` chain.
- **Immutability:** trigger-blocked `UPDATE`/`DELETE`; `UPDATED_AT = null` (single
  `created_at`). Verified by `audit:verify-chain` (per-merchant + platform).
- Full column list is stable since R2 (`ulid`, `merchant_id`, `branch_id`, `actor_id`,
  `actor_label`, `action`, `severity`, `auditable_type`, `auditable_id`, `context`,
  `ip_address`, `correlation_id`, `previous_hash`, `hash`, `created_at`).

## `audit_flagged_events` (Phase 19)

- **Purpose/scope:** one **review record** over exactly one branch-scoped `audit_logs`
  row. It is the Audit-role queue item: an auditor flags a suspicious event, works it
  through a review lifecycle, and records a metadata outcome. It **never** changes the
  audited source row, any operational/financial/identity record, or the audit chain —
  only its own review metadata (`status`, `review_notes`, `assigned_to`, `resolved_by`).
- **Tenant ownership:** **branch-owned** (`BelongsToMerchant` + `BelongsToBranch`).
  `merchant_id` and `branch_id` are copied from the audited row at flag time and must
  match it; only branch-scoped audit rows (non-null `merchant_id` AND `branch_id`) are
  flaggable, which keeps the branch-scoped Audit role's queue coherent (Plan §10, §15;
  merchant-level/platform audit rows are out of the Phase 19 flag workflow's scope).
- **Soft delete:** **none.** There is no `deleted_at` and no destructive delete —
  review history is preserved; a mistaken flag is `dismissed`, not removed.
- **Immutability of linkage:** `audit_log_id` is write-once and `ON DELETE RESTRICT`
  (audit rows are never deleted regardless). `created_by` is write-once. Status changes
  only through the flagged-event state machine (no mass assignment, no controller writes).

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `bigint generated by default as identity` | no | — | internal PK, never exposed |
| `ulid` | `char(26)` | no | — | unique public identifier + route key |
| `merchant_id` | `bigint` | no | — | FK→`merchants.id` `ON DELETE CASCADE`; copied from the audited row |
| `branch_id` | `bigint` | no | — | FK→`merchant_branches.id` `ON DELETE CASCADE`; copied from the audited row |
| `audit_log_id` | `bigint` | no | — | FK→`audit_logs.id` `ON DELETE RESTRICT`; the immutable source row |
| `status` | `varchar(16)` | no | `open` | CHECK `open`/`under_review`/`resolved`/`dismissed`/`reopened` |
| `review_notes` | `varchar(2000)` | yes | — | reviewer notes; required for a terminal outcome |
| `assigned_to` | `bigint` | yes | — | FK→`users.id` `ON DELETE RESTRICT`; required while `under_review` |
| `resolved_by` | `bigint` | yes | — | FK→`users.id` `ON DELETE RESTRICT`; required for `resolved`/`dismissed` |
| `created_by` | `bigint` | no | — | FK→`users.id` `ON DELETE RESTRICT`; the flagging auditor |
| `created_at` / `updated_at` | `timestamptz` | yes | — | standard timestamps |

**Constraints / indexes:**

- `audit_flagged_events_status_check` — `status IN (open,under_review,resolved,dismissed,reopened)` (mirrors `AuditFlaggedEventStatus`).
- `audit_flagged_events_resolution_check` — `(status IN (resolved,dismissed)) = (resolved_by IS NOT NULL AND review_notes IS NOT NULL)`.
- `audit_flagged_events_assignment_check` — `status <> under_review OR assigned_to IS NOT NULL`.
- `audit_flagged_events_branch_merchant_foreign` — composite FK `(branch_id, merchant_id) → merchant_branches(id, merchant_id)` (R5 tenant consistency).
- Indexes: `(merchant_id, branch_id)`, `(branch_id, status)` (queue filter/sort), `(audit_log_id)`; `UNIQUE(id, merchant_id)` for composite-FK targets; `UNIQUE(ulid)`.
- **No uniqueness rule on `audit_log_id`** — the Plan/Scope do not mandate one, so a
  Plan-absent uniqueness constraint is not invented (multiple historical flags on one
  row are permitted; the workflow discourages duplicate open flags at the action layer).

**Query patterns:** branch-scoped queue by `(branch_id, status)` sorted by `created_at`;
detail by `ulid` resolved **inside** tenant scope (foreign ULID → non-enumerating 404).

**Masking:** the flagged-event Resource exposes the public `ulid`, `status`, review
metadata, and a **masked** projection of the linked audit row (safe action name,
severity, actor label, masked context) — never internal ids, tokens, signed URLs,
storage paths, SQLSTATE, or unmasked PII (Plan §9, §24).

**Retention:** retained with the audit record it reviews (audit retention, Plan §74); no
independent purge — review history is part of the audit trail.

**Locking/concurrency:** transitions take a row lock (`lockForUpdate`) inside a
transaction and re-check the current status against the state machine, returning
`422 invalid_state_transition` on a stale/invalid move.

**Transition actions / audit events:** `FlagAuditEvent` (→`open`,
`audit.flagged_event.created`), `StartFlaggedEventReview` (→`under_review`,
`audit.flagged_event.review_started`), `ResolveFlaggedEvent` (→`resolved`,
`audit.flagged_event.resolved`), `DismissFlaggedEvent` (→`dismissed`,
`audit.flagged_event.dismissed`), `ReopenFlaggedEvent` (→`reopened`,
`audit.flagged_event.reopened`). Each records a typed `AuditEvent` through
`AuditRecorder`.

**Factory & tests:** `AuditFlaggedEventFactory` (+ `AuditLogFactory` test-only source);
`AuditFlaggedEventSchemaTest`, `AuditFlaggedEventStateMachineTest`,
`AuditFlaggedEventWorkflowTest`, `AuditFlaggedEventIsolationTest`,
`AuditSourceMutationDenialTest`.

**Migration order / forward-repair:** `2026_07_04_000001_create_audit_flagged_events_table.php`
(create; forward-only). Correction ships as a new forward migration; `down()` is
local/CI convenience only (ADR-004).

## `audit_exports` (Phase 19 — product-owner decision 2026-07-04, ADR-010)

- **Purpose/scope:** one async, reason-gated, permission-masked, signed/expiring,
  download-counted **Audit export request** over branch-scoped audit data (Plan
  export-controls invariant; §19.2/§19.3 `audit.export`, SU Y, high; §13.5 DDL). Mirrors the
  `finance_exports` request lifecycle but is Audit-owned. Resolves REM-AUDEXP-001 (why not
  `uploaded_files` alone / `finance_exports`: see `docs/proof/phase-19.md` capability matrix).
- **Tenant ownership:** **branch-owned** (`BelongsToMerchant` + `BelongsToBranch`), `branch_id`
  **NOT NULL**; the requested branch must be one of the requesting Audit user's active assigned
  branches. Registered in `TenantOwnership` (BRANCH_OWNED + MODELS `'branch'` +
  COMPOSITE_CONSISTENCY) and the migration manifest. Public **ULID** only.
- **Columns:** `id`; `ulid` (unique, route key); `merchant_id`; `branch_id` NOT NULL;
  `requested_by_user_id` FK `users` RESTRICT; `reason` varchar (non-empty CHECK); `scope_json`
  jsonb (validated filter snapshot only — date range, event domains, severities, branch);
  `status` varchar CHECK `('queued','processing','ready','failed','expired','revoked')`;
  `file_id` FK `uploaded_files` RESTRICT nullable; `row_count` int nullable (null before ready,
  ≥0 after); `download_count` int default 0 (≥0); `first_downloaded_at`/`last_downloaded_at`
  nullable; `requested_at`; `processing_started_at`; `generated_at`; `failed_at`; `expires_at`;
  `revoked_at`; `expired_at`; `failure_code` varchar nullable; `failure_message_redacted`
  varchar nullable; `created_at`/`updated_at`.
- **Invariants (DB CHECKs + FKs):** non-empty `reason`; `download_count ≥ 0`;
  `first_downloaded_at` null iff `download_count = 0`; `last_downloaded_at` null iff
  `download_count = 0` and `≥ first_downloaded_at`; `row_count` null unless `ready`/`expired`/
  `revoked` and `≥ 0` when set; `ready` ⇒ `file_id`+`generated_at`+`expires_at`+`row_count`;
  `failed` ⇒ `failed_at`+`failure_code`; `revoked` ⇒ `revoked_at`; `expired` ⇒ `expired_at`;
  composite `(branch_id,merchant_id)→merchant_branches`; `UNIQUE(id,merchant_id)`;
  `file_id` ON DELETE RESTRICT. **No** soft delete; **no** destructive delete workflow.
- **State machine:** `AuditExportStateMachine` — `queued→processing→ready|failed`,
  `ready→expired`, `ready→revoked`, `failed→queued` (retry only via an authorized transition;
  no invented retry endpoint). Status is never assigned directly.
- **Masking / safety:** generated via `GenerateAuditExport` (reports-exports, `TenantAwareJob`),
  querying by `merchant_id` + the snapshotted `branch_id`, applying only validated filters and
  `AuditValueMasker`, writing a private CSV through the Phase 10F file domain
  (`FilePurpose::AuditExport`, `GeneratedFileWriter`). **Merchant-level (`branch_id` null) audit
  rows are never exported.** The table stores **no** raw export contents, storage paths, signed
  URL signatures, full contacts/references, tokens, SQLSTATE, or stack traces.
- **Download accounting:** on the authorized file **STREAM** (not link issuance) via
  `RecordAuditExportDownload` (row-locked, atomic): `download_count++`, `first_downloaded_at`
  once, `last_downloaded_at` each time, emit `audit_export.downloaded`. Authorization is
  re-checked at both link issuance and stream (`FileAccessService`).
- **Typed events:** `audit_export.requested|generated|failed|downloaded|expired|revoked`
  (Finance-export naming convention; the unused `audit.exported` catalogue entry is retired).
- **Factory & tests:** `AuditExportFactory`; `AuditExportSchemaTest`, `AuditExportWorkflowTest`,
  `AuditExportMaskingTest`, `AuditExportIsolationTest`, `AuditExportAuthorizationTest`,
  `AuditExportStepUpTest`, `AuditExportExpiryDownloadCountTest`, `AuditExportJobIdempotencyTest`,
  `AuditExportAuditTest`.
- **Migration order / forward-repair:** `2026_07_04_000002_create_audit_exports_table.php`
  (create; forward-only) + `2026_07_04_000003_add_audit_export_to_uploaded_files_purpose_check.php`
  (expand the `uploaded_files` purpose CHECK; expand/contract — no shipped migration edited).
