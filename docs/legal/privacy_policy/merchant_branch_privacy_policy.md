## 4. DESCRIPTION OF SERVANA

4.1. Servana is a multi-tenant SaaS web platform for service-based SMEs, including barbershops, salons, massage parlours, spas, grooming studios, beauty parlours, and similar appointment-based or walk-in businesses.

4.2. Servana is designed to operate as a service-operations platform through which merchant businesses can digitise, control, and audit day-to-day operations, including merchant onboarding, merchant branches, staff and personnel access, front-office operations, client records, walk-ins, appointments, queue management, service delivery tracking, client choice of next available personnel or preferred personnel, invoice generation, offline payment recording, receipt generation, personnel commission visibility, client data protection, contact access control, platform fee calculation, service fee tier invoice pricing, merchant financial visibility, and audit-ready operational and financial records.

4.3. Servana must not be treated solely as a booking application, point-of-sale system, payment processor, invoicing tool, staff roster, or reporting tool. It is a service-operations SaaS platform intended to help Customers run clients, staff, services, queues, invoices, commissions, platform fees, reports, and audit records from one secure web dashboard.

4.4. Servana is structured around tenant isolation. Each merchant operates as an isolated tenant. A merchant’s data must not be accessible, inferable, editable, exportable, or enumerable by another merchant, subject only to controlled Citrus Labs Limited platform-level workflows, lawful support access, security operations, legal compliance, billing enforcement, abuse controls, and other lawful exceptions.

4.5. Servana records offline or off-platform payments. Servana may record payment method, amount, reference, status, validation details, payment notes, partial payment records, split payment records, external refund records, cash-up records, reconciliation records, disputes, receipts, and related audit trails, but Servana does not, by this Policy alone, represent that it directly processes client-to-merchant payments inside the platform.

4.6. Servana includes Branch management functions that permit the Merchant Branch user, within the assigned Branch scope, to manage the specific Branch profile, Branch operating hours, Branch operating calendar, Branch service configuration, Branch service pricing, Branch queue configuration, Branch appointment controls, Branch day opening and closing, Branch cash-up and reconciliation submissions, Branch reports, Branch invoices, Branch receipts, Branch payment records, Branch audit logs, and operational reassignment of affected queue entries or appointments where Merchant Personnel become unavailable.

## 5. MERCHANT BRANCH ROLE AND PRIVACY TREATMENT

5.1. The Merchant Branch account represents a physical or operational business location created by the Merchant Administrator. The Merchant Branch user manages only the specific Branch account into which that user has been added or assigned.

5.2. The Merchant Branch user does not create Merchant Branch accounts, does not manage external branches, does not assign merchant users to branches, does not handle branch-scoped access permissions, does not perform Merchant Human Resource personnel-assignment duties, does not create, activate, suspend, or deactivate merchant staff users, and does not override HR-controlled personnel service eligibility.

5.3. The Merchant Branch user may manage the specific Branch profile, including Branch name, Branch code, physical address, town, city or area, phone number, optional Branch email, business category where inherited or overridden, and Branch status.

5.4. The Merchant Branch user may manage the specific Branch operating hours and operating calendar, including weekly operating hours, public holiday exceptions, special closures, break periods, same-day emergency closure, closure reasons, and related schedule audit trails.

5.5. The Merchant Branch user may configure services and pricing within the specific Branch account, including service categories, price, estimated duration, Branch availability, active or inactive status, discount support where enabled, preferred personnel fee eligibility, and service-level revenue performance reporting, subject to HR-controlled personnel service eligibility and Servana’s role boundaries.

5.6. The Merchant Branch user may view real-time, read-only HR-controlled personnel visibility for the specific Branch only, including assigned personnel state, personnel availability schedules, working days, shifts, breaks, unavailable times, temporary unavailability, sick leave, emergency leave, no-show, break, active or inactive for queue, skill or service eligibility, and reassignment rules. Such visibility does not grant HR authority.

5.7. The Merchant Branch user may view and manage Branch queues, Branch appointments, Branch reports, Branch revenue, Branch invoices, Branch receipts, Branch payment records, Branch-level audit logs, Branch dashboard cards, Branch day opening and closing workflow, Branch cash-up and reconciliation submissions, and operational reassignment where affected queue entries or appointments must be transferred from an unavailable Merchant Personnel user to another eligible Merchant Personnel user.

5.8. Branch status may affect Processing and operational access. An active Branch may accept appointments, walk-ins, queues, invoices, payments, and service sessions. A suspended Branch may be prevented from accepting new walk-ins or appointments while historical records remain visible. An archived or closed Branch may no longer be operational and must not be closed or archived while live operational records exist.

5.9. Because the Merchant Branch role is operational, the Merchant Branch user’s actions may be extensively logged, including Branch profile edits, Branch status changes, operating hours changes, special closure additions, service enablement or disablement, queue opening and closure, queue reordering, appointment changes, service session actions, invoice views or actions, payment-record views, receipt views, Branch day opening and closing, Branch day reopening, cash-up submission, report views, unauthorised access attempts, IP address, user agent, timestamp, and related audit metadata.
